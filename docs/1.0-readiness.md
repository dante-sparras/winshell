# 1.0 readiness

**Verdict: not ready for 1.0.** The implementation covers the roadmap, but a green test suite does not close the runtime, delivery and live-validation gaps below. This is an audit of `4689259f824d015608f11fc6454749d9312cda0c` (v0.6.0), performed on 29 October 2026. Later fixes need their own evidence; merging this document does not approve a release.

The item numbers are from the external planning survey dated 28 October 2026, supplied by the project lead. That survey was never committed and is not reproduced here. The accepted ADRs take precedence over its original options: Winshell has its own Windows API, uses DirectWrite over the Skia scene, runs alongside Explorer, and asks Windows to lock rather than drawing a lock screen.

## Verification on the audited commit

`pwsh scripts/check.ps1` exited 0 with zero build warnings, zero build errors and a clean DocFX build. All 930 tests passed: 16 parser, 214 runtime, 671 Windows platform and 25 CLI tests, followed by one isolated platform reload-leak test and three isolated Jint budget tests. The native capture test returns without probing Windows unless explicitly opted in; its passing result does not establish live capture coverage.

A repeat of the full check while adding this audit failed in `MediaTests.A_session_reports_metadata_artwork_and_controls`: its session wait returned null at line 102. That is the older session-discovery symptom, rather than the missing-duration assertion in #131. The runtime was unchanged. The initial green run therefore establishes coverage, not suite reliability; the test fix must account for discovery as well as independently arriving timeline data. A single rerun after rebasing the audit branch passed all 930 tests again with zero warnings.

The Jint measurements were 4.941 microseconds and 640 bytes per binding evaluation, 1.144 milliseconds and 274,384 bytes to start an engine, and 65.135 milliseconds and 9,733,216 bytes to load the typical shell. These are this run's measurements, not a hardware-independent promise or an idle-power measurement.

A temporary configuration opened one floating window with text and an `IpcHandler`. The built executable registered its own instance, answered `ipc --pid <owned-pid> call probe ping`, and changed its response from `sol-ready` to `sol-reloaded` after the QML file changed. `doctor --path <temporary-config> --json` exited 0 with 10 passes, no warnings and no failures. The instance exited through `kill --pid <owned-pid>`. No default taskbar, tray host, sign-in registration or Windows setting was changed by this smoke configuration. Both smoke attempts were closed; the first also completed IPC and doctor, but its evidence script read stdout instead of stderr when counting log lines, so reload was verified by the changed IPC response on the second attempt.

The automated suite also creates its own test windows and media session. It does not establish every real-device action. Installer Pester tests are a separate CI job, not part of `check.ps1`; they were not run locally for this audit. The [CI run on the audited commit](https://github.com/dante-sparras/winshell/actions/runs/40859001840) passed, including that installer job. No machine-wide software or certificate was installed for this audit.

## Gates before the release decision

1. Reproduce and close the native surface-lifetime concern in #151. A bitmap/swap chain must remain alive through an in-flight frame, including when QML destroys its window from layout. Its current report is based on code inspection, not a crash reproduced by this audit.
2. Fix the media test's readiness race (#131), without dropping metadata/control assertions. Rerunning a green test does not prove this intermittent fault absent. Resolve or explicitly accept the other recorded CI timing failures (#146/#152).
3. Complete the security pass and disposition the known report-redaction gap (#135). That issue is public already; a newly discovered vulnerability must follow the [private reporting policy](https://github.com/dante-sparras/winshell/blob/main/.github/SECURITY.md).
4. Prove public artifact delivery after #166, then a real portable update and the intended signing/distribution path. #142 must be fixed before shipping a Store build that offers sign-in startup. This audit does not change repository settings, publish assets or supply credentials.
5. Record a human acceptance pass for current native fidelity: Narrator, CJK IME, physical mixed-DPI/hot-plug, contrast themes, materials, tray interoperability and the intended device actions. Existing automated tests and the historical spike leave these unverified. Dante decides which hardware/deployment matrix is required.

Documented advanced API limitations (#137–#139/#149) need explicit release scope rather than an assertion that every exported API is complete. The missing convenience reload command (#134), deterministic packaging/token hygiene (#130), parsing resource bounds ([#164](https://github.com/dante-sparras/winshell/issues/164)) and IPC resource/lifetime bounds ([#165](https://github.com/dante-sparras/winshell/issues/165)) are labeled `post-1.0`. The last two are local availability limits, not demonstrated privilege bypasses. A deferred issue is not evidence that its behavior works.

Every runtime or security fix requires a separate green PR and the requested independent review. A release waits for Dante's approval after those gates; no version-bump commit is part of this work.
