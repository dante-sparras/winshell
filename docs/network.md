# Windows networking

`shell.Networking` is a [NetworkingService](reference/winshell-network.md#networkingservice). Reading it reads state and subscribes to Windows network notifications. It never requests permission or changes a connection or a radio on its own. Setting `WifiEnabled` asks Windows to change the Wi-Fi radios.

`Devices` contains physical wired and Wi-Fi adapters, with Windows adapter `Id`, `Name`, MAC `Address`, `State`, and `Networks`. `WifiDevice.Mode` is read with that snapshot. An extensible station is `Station` and an extensible access point is `AccessPoint`. Windows 11 does not report an ad-hoc network, so `AdHoc` is never returned, and Windows has no 802.11s source, so `Mesh` is never returned. Any other operation mode, or a query that fails, is `Unknown` and the rest of the snapshot still arrives. The read does not use the current connection or the BSS list, so it does not need location access. A wired adapter has no `Mode`. `WifiDevice.Scan` performs one scan, exposes `Scanning` while pending, and updates `Networks`. No periodic scan runs in the background. Network objects retain identity by adapter and SSID. Wi-Fi `SignalStrength` is normalized to 0–1. `Security` describes authentication. `Saved` is true when a loaded profile's SSID matches the network, including a connected network the last scan did not report. A profile that could not be read matches by its profile name instead. `Network.Forget` deletes the saved profile whose name is that SSID, and only when called. Wired `HasLink` and `LinkSpeed` (Mbps) describe the physical link. Windows manages wired connections automatically.

`SavedProfiles` lists every saved profile for that SSID. More than one can share an SSID. A saved SSID that is not in range has no network object. `WifiProfile.Name` is the profile name Windows stored. `Forget` and `ConnectWithProfile` use that name, and it can differ from `Ssid`. `AutoConnect` is the profile's connection mode. It stays at the last reported value until a later read shows the change. Setting it rewrites only that element. `ClearPassword` removes the key element and leaves every other element, including ones Winshell does not interpret. Neither call reads the password. `HasPassword` is true when a key element is present. `Read` returns those fields and never a key. `ConnectWithProfile` asks Windows to connect with that profile, including the hidden-network flag when the profile says `nonBroadcast`. The call finishes when Windows accepts the request. The following snapshot reports whether the adapter associated. These writes run off the UI thread, one at a time. Reading a snapshot does not write a profile. Windows refuses a non-admin change to an all-users profile, and that failure is reported.

`Profiles` contains Windows `NetworkInformation.GetConnectionProfiles()` entries, including profiles on virtual adapters. These are connection profiles, not the saved WLAN profiles in `SavedProfiles`. A profile exposes `Id`, `Name`, `AdapterId`, `Connectivity`, `Cost`, `Metered`, `Roaming`, `OverDataLimit`, `SignalAvailable`, and `SignalStrength`. Cost is `Unknown`, `Unrestricted`, `Fixed`, or `Variable`. `Metered` is true for fixed or variable cost, roaming, or an exceeded data limit. The service's `Connectivity` follows Windows NCSI: `Unknown`, `None`, `LocalAccess`, `CaptivePortal`, or `InternetAccess`.

`WifiState` is `Unknown`, `On`, `Off`, or `Disabled`, aggregated across Wi-Fi radios. `WifiEnabled` means at least one reports On. `WifiHardwareEnabled` means at least one reports On or Off. Both are false when radio information is unavailable. Inspect `WifiState` to distinguish that case. `WifiState` and `WifiHardwareEnabled` stay read-only. Setting `WifiEnabled` asks Windows to turn every Wi-Fi radio on or off, through `Radio.RequestAccessAsync` and then `Radio.SetStateAsync` for each radio that is not already there. The property keeps the last reported value until Windows reports the new one. A refusal, or a radio that does not reach the requested state, sets `Error` and raises `OperationFailed`. Turning off leaves a radio that is not on, including a disabled one, as it is. Turning on asks a disabled radio too, and Windows may refuse. If one radio changes and a later one refuses, the earlier change stands. An allowed request can still leave the radio where hardware or policy put it. Listing adapters needs no permission to control radios. The first change can show Windows' radio-control consent. Reading the service does not, and neither does setting the value the radios already have. A packaged app declares the `radios` device capability. `RequestAccess` is the separate permission for scanning and connecting.

`AirplaneMode` is read-only: `Unknown`, `Off`, or `On`. There is no public aggregate WinRT airplane-mode API. Winshell reads the persisted `HKLM\SYSTEM\CurrentControlSet\Control\RadioManagement\SystemRadioState` DWORD as a best-effort Windows implementation detail (0 off, 1 on). Missing, unexpected or inaccessible values produce Unknown. This is not a guaranteed real-time radio state. Call `Refresh` to reread it. Never infer airplane mode from Wi-Fi or Bluetooth being off: Windows permits overriding individual radios in airplane mode.

Wi-Fi scan and connect require Windows Wi-Fi and location access. Call `RequestAccess` from a user action. This may show Windows consent UI. Observe `RequestingAccess` and read-only `AccessStatus` (`Unspecified`, `Allowed`, `DeniedByUser`, `DeniedBySystem`). Desktop location policy and, for packaged deployments, the `wiFiControl` capability determine availability. Repeat the request after permission changes or adapter insertion. Reading the service does not request permission. See Microsoft's [Wi-Fi access and location changes](https://learn.microsoft.com/en-us/windows/win32/nativewifi/wi-fi-access-location-changes).

Actions expose `Busy` and `Error` on networks, `Scanning` and `Error` on Wi-Fi adapters, and `Error` on the service. `OperationFailed` reports action failures, including a refused radio change. Overlapping actions on the same object are ignored while busy, and a second `WifiEnabled` change is ignored until the first has finished. Completion only clears the pending flag. The next Windows snapshot supplies actual connection and radio state. Permission revocation, unavailable networks, unsupported authentication, invalid passwords and Windows errors do not imply success. `Connect` uses Windows automatic reconnection for the explicitly selected network. `ConnectWithPassword` is for a secured network that is not saved. The password is not kept.

The default shell's Wi-Fi tile opens Windows Settings. It does not set `WifiEnabled`.
