# Draw text with DirectWrite and expose controls to UI Automation

**Status:** accepted

ADR 0002 still paints the item tree with one Skia scene, and ADR 0003 still puts Mica, Acrylic, or nothing on the HWND. A XAML renderer stays rejected: it would split the QML tree from the pixels, and an island would sit in its own airspace over that scene. Text is the exception. Draw it with DirectWrite, grayscale where a backdrop shows through, and expose the built-in controls through UI Automation so Narrator can reach them. WinUI 3 is the visual reference for a later token pass, not the host.

A panel of one button, one toggle, one slider, one text field, one list, and one popup was compared with the same controls in an unpackaged WinUI 3 window on Mica. WinUI 3 Gallery is not installed. System DPI stayed at 96 and the system theme stayed dark. Light frames flipped theme inside the process. "Save changes" at 14 px measured 83.43 px with Skia and 83.36 px with DirectWrite. The shell reached a first frame in 2272 ms (Skia) and 2470 ms (DirectWrite), then sat near 0% CPU, at 162 MB and 175 MB. The WinUI process reached activation in 432 ms at 134 MB. That process is only the panel. Skia exposes the window chrome alone. The provider exposes the panel, including the popup text. The toggle is a button named Wi-Fi, which is also how WinUI reports it, because UI Automation has no Switch type. A synthetic composition, with no CJK keyboard installed, committed あ from `WM_IME_CHAR` and nothing from the composition or result strings. No candidate window was drawn. Dark Mica sampled `#545454` and light `#F3F3F3`. The Skia accent button was `#B1CEC8` in dark and `#648B82` in light. The WinUI accent button was `#7DAEA3` with a white label and a focus rectangle. The 150% and 200% Skia and DirectWrite frames are a renderer scale, not a change of the system DPI. Both windows were placed back to a 1274×660 client. Only the WinUI dark 150% frame changed size, and that capture includes a black band under the painted surface.

The remaining work is the provider across the built-in controls, focus and live regions, a real IME composition window, and the token pass that closes the accent-button gap. Hosting WinUI for the shell is a rewrite of the scene and of every configuration that draws its own items.
