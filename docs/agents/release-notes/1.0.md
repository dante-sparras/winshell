# Winshell 1.0

These notes are a draft for the 1.0 announcement. 1.0 is not tagged. [CHANGELOG.md](https://github.com/dante-sparras/winshell/blob/main/CHANGELOG.md) is the version-by-version log and is not edited here.

This is what changed for someone using Winshell since 0.1, grouped by area. 0.2 through 0.6 are the releases after 0.1.6.

## The shell

Winshell ships a default shell that looks like Windows 11 and runs next to Explorer. It does not hide or replace Explorer's taskbar.

- A taskbar on every screen, with pinned apps, live window previews, keyboard access and Narrator.
- Start, with pinned apps, recommendations and search.
- Quick settings: Wi-Fi, Bluetooth, volume, brightness, battery, the sound output, and the playing media. Tiles can be edited and reordered.
- A notification center and a calendar that follow the regional clock. A notification from today uses the short time; an older one keeps the weekday.
- On-screen displays for volume, brightness, media and mute.
- Winshell Settings, laid out like Windows Settings, for the taskbar, Start, quick settings, hotkeys and signing in.
- **Run Winshell when I sign in**, which Windows' Startup apps page can turn off.
- A Windows 11 notice when the configuration has an error, or when a window fails to open.
- Light mode, dark mode, contrast themes, and an accent color the shell can choose.

## Windows

The configuration reads Windows, instead of a Linux desktop.

- Apps from the Start menu, with search.
- The window list, moving a window to another monitor, and virtual desktops.
- Live previews drawn by the Desktop Window Manager, and which windows are flashing for attention.
- Playback devices and audio sessions.
- Wi-Fi profiles and explicit network actions.
- Bluetooth state and explicit device actions.
- System media sessions.
- The notification center, and sending a toast.
- Battery, power mode and monitor brightness.
- Screen capture.
- Global hotkeys registered from QML.
- The notification area: names, overflow, hidden icons, balloons, icons that stay sharp at every scale, and handing the tray back when Explorer restarts.
- Panels that reserve a screen edge, including after another bar leaves.
- Windows placed on monitors that do not share a DPI.
- Text drawn with DirectWrite, and the built-in controls exposed to Narrator through UI Automation.
- Buttons, menus, sliders, text boxes and the other controls drawn with WinUI 3's colors.
- Locking the PC stays with Windows. Winshell has no lock screen of its own.

Module names are the Windows ones (`Winshell.Audio`, `Winshell.Windows`, and the rest). Quickshell's names are in [Migrating from Quickshell](../migrating-from-quickshell.md).

## Configuration

A shell is QML. Winshell parses it and runs the JavaScript on Jint. Items are drawn with Skia, in DirectComposition windows, with Mica and Acrylic.

Configurations live in `%APPDATA%\winshell`. Winshell Settings, Start's pins and the quick settings tiles are TOML: `preferences.toml`, `launcher.toml` and `quick-settings.toml`. There is no import of the old JSON files. `taskbar.json` is still JSON, and it is app state, not those settings.

Saving a `.qml` or `.js` file the configuration loaded reloads the shell. There is no `winshell reload` command ([#134](https://github.com/dante-sparras/winshell/issues/134)).

## Install, updates and finding what is wrong

- **Build from source** with the .NET 10 SDK, when you want a build that does not update itself.
- **Portable zip** on the GitHub release: `winshell-<version>-win-x64.zip` and `winshell-<version>-win-arm64.zip`, plus `SHA256SUMS.txt`. It needs no .NET install, and it updates itself from GitHub Releases.
- **PowerShell**, for the current user, no administrator: `irm https://github.com/dante-sparras/winshell/releases/latest/download/install.ps1 | iex`. It checks the zip against `SHA256SUMS.txt`. `uninstall.ps1` removes that install and leaves the configuration.
- **winget**, coming. `winget install DanteSparras.Winshell` once winget has accepted the package. Not available yet.
- **Microsoft Store**, coming. The package is built in CI. Publishing waits on Partner Center. Not available yet.
- **SignPath**, coming. Release binaries will be signed once the SignPath Foundation project is approved. Published zips are unsigned until then.

`winshell doctor` checks this PC and says how to fix what it finds. A crash writes a report under `%LOCALAPPDATA%\winshell\crashes` and does not send it anywhere. A window that fails to open closes and tries again. The docs site is built from `docs/`.

## Known limitations

- 1.0 is not tagged. Until it is, a release can still break a configuration.
- winget, the Store and SignPath signing are not available yet. The portable zip and the PowerShell installer are. winget, the Store and SignPath wait on Dante's setup.
- A window destroyed while its own frame is drawing can free its surface in the middle of that frame. It has not been seen happen ([#151](https://github.com/dante-sparras/winshell/issues/151)).
- The Store package's sign-in is its startup task, declared off, so a Store update does not leave a path ([#142](https://github.com/dante-sparras/winshell/issues/142)). The call that enables that task has not been run inside an installed package. The package is not published.
- Some Qt Quick members load and then do nothing. The list is [Where Winshell differs from Qt](../reference/qt-quick.md#where-winshell-differs-from-qt). Other Winshell members are named and unused ([#137](https://github.com/dante-sparras/winshell/issues/137), [#149](https://github.com/dante-sparras/winshell/issues/149)).
- A few service values do not match the page that describes them: audio links stay empty, `Audio.ready` stays true when audio failed to open, and the virtual desktop list does not notice a desktop added or renamed in Task View until the next switch ([#139](https://github.com/dante-sparras/winshell/issues/139)). A few properties change without telling a binding ([#138](https://github.com/dante-sparras/winshell/issues/138)).
- Crash reports drop some of Winshell's own log lines, and redaction is best effort ([#135](https://github.com/dante-sparras/winshell/issues/135)).
- Screen capture is SDR. HDR picture can look clipped. There is no bypass of content protection.
- Hearing Windows notifications needs the listener permission. The unpackaged build does not declare that package capability. The Store package does, once it is published. Some PCs already allow an unpackaged host.
- Winshell does not replace Explorer. Both taskbars can sit on the bottom edge until Explorer's is set to hide.
